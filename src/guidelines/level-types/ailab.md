# AI Lab

## Purpose

Lab2 prototype of AI Lab. The student workspace is two experiences: **Data Set** (an immersive spreadsheet with a Train rail) and **Testing** (a prediction dashboard). There is no Train tab. Training lives in a right-hand **TRAIN** rail on Data Set. Lab2 Continue leaves the level.

Source intent: [PR #74600](https://github.com/code-dot-org/code-dot-org/pull/74600) (`ai-studio-prototype`) and the Data Makes AI handoff.

The **full studio** (`/levels/ailab`) is the end-state prototype: student-chosen dataset and algorithm, scorecard, and export. Levelbuilder knobs (algorithm, dataset, tabs, train, export, sheet edit, default view) are all wired through the **Dev** panel on every AI Lab route so the same chrome can demonstrate guided, curriculum, and standalone-project shapes without extra routes.

Classic three-tab chrome (`AiLabWorkspace` + Dataset / Train / Test) is still in the repo for pullback (`workspace="classic"`). Current routes use `AiLabGuidedWorkspace`.

## Routes

| Route | Name | Export | Index section | Default shape |
|---|---|---|---|---|
| `/levels/ailab` | Train a model | `AiLabLevelPage` | Lab environments | Full studio: setup modal, scorecard, export |
| `/levels/ailab-pretrained` | Audit a model | `AiLabPretrainedLevelPage` | Lab environments | Lands on Test with a finished Decision Tree; Data hidden; scorecard available |
| `/levels/ailab-guided` | Train a model (guided) | `AiLabGuidedLevelPage` | Lab environments | P0 chrome; weekday distractor dataset locked; 25 rows |

Tree nodes carry `labelCounts`; `decisionTree.ts` also exports `treeBranches`, `summarizeTree`, `countLeaves`, `subtreePredictions` for the viz. `knn.ts` is textbook unweighted majority-vote (ml-knn 3.0.0 style): Euclidean nearest k, one vote each, first class to hit the winning count in neighbor order. It exports `knnDistances`, `neighborFeatureDeltas`, `knnVotes`, `majorityVote`, `summarizeVotes` (top-5 vote sentence with "and N others"), `classificationKCandidates`, and `regressionKnnK`. Studio trains KNN with a 10% end holdout: classification searches `{1, 3, 5, 7, 17, 31, 45, 61, √n}` (k = n when n ≤ 10; `n/3` was dropped because on signal-less features it "wins" the holdout by degenerating into a majority-class guesser with hundreds of neighbors); numeric labels skip the search (`k = 1` if n < 100, else `k = 5`) and score a prediction as correct when it is within 5% of the label column's range. Guided levels with `defaultKnnK` lock k and score leave-one-out on the sheet. Categoricals are ordinal integers in first-seen sheet order (`firstSeenValues` in `encode.ts`), not one-hot and not the sorted `uniqueValues` used by the analysis dock. `columnStats.ts` caches `uniqueValues` / `frequencies` / `numericalStats` per column in a `WeakMap` keyed on the `rows` array; `knn.ts` caches the encoded `Float64Array` feature matrix per (rows, features); `decisionTree.ts` evaluates numeric thresholds in a single sorted sweep of running label counts. `cardinality.ts` is the categorical-cardinality guardrail mirrored from production AI Lab: `MAX_CATEGORY_VALUES` (50) blocks a categorical column with more values as label or feature, `LABEL_FOLD_THRESHOLD` (8, the palette size) marks a label as "crowded"; `labelNotice` / `featureNotice` return the `{ sentiment, text }` the Train rail shows as dropdown helper text

## CADS consumption

Workspace chrome uses packaged CADS via `Lab2Shell` → `CadsLabProvider`: `Button`, `Modal`, `Radio`, `Dropdown` (with `label` / `helperText`), `Tabs` (classic pullback rail), `TextInput`, `Tag`, `SegmentedButton` (incl. `iconOnly`; workspace header Data Set / Testing), `Tooltip`. Panel headers reuse the shared `PanelHeader` (`src/components/ui/PanelHeader.tsx`). Local SCSS uses unprefixed Foundations (`--background-*`, `--text-*`, `--shape-*`).

The workspace is full-bleed Lab2 chrome (header + tab rail + edge-to-edge panels), not the inset floating cards used by AI Chat Lab.

Visualizations are hand-rolled SVG + HTML rather than a graph editor, in the spirit of the [decision-tree POC](https://github.com/code-dot-org/code-dot-org/pull/75114): a left-to-right readable tree instead of a node-canvas. Production trains with `ml-cart`; this prototype still uses a local multi-way ID3-style trainer so categorical splits stay labeled as values (`salsa is hot`) instead of ordinal thresholds (`salsa < 0.5`).

- Decision Tree: HTML nodes (`role="tree"` / `treeitem`) positioned by `treeLayout.ts`; SVG under them draws only the connectors (`aria-hidden`). No visx.
- KNN: Target and Table views are plain SVG/HTML. No visx anywhere in the AI Lab viz folder.
- Both share `VizFrame` (canvas; Test owns the chrome strip), `NavigatorCard` + `TraceBar` (Play + stepper; floating card on both algorithms) — or `CanvasCards` + `TraceBar` under the `canvas` Testing layout — and the same label color order from `labelPalette.ts`, so the legend colors on the tree's distribution bars match the KNN dots.

## Current UX Behavior

- Resource panel: Instructions (swap by section), Continue, Dev. AI Tutor, Version History, and Backpack are off.
- Lands on **Data** unless the level hides that tab. One **setup modal** (CADS Modal, not stacked dialogs) collects dataset and algorithm in the same view. A locked/pre-selected side is omitted. Compact choice rows. Test stays locked until a model exists (or the level ships a pretrained model).
- **Data Set** is a native spreadsheet by default (`defaultDataView: "cards"` lands on Cards instead). A 40px **dataset header** sits above the sheet: an extra-small outlined **dataset chip** (name + `right-left` when pickable; opens setup like the header algorithm chip) · **N rows** on the left; on the right an extra-small contained secondary **Add row** (`plus`, table only, hidden when `allowDataEdit` is false) · an icon-only Table / Cards segmented control (plus catalog / carousel when Cards is active). Click a cell to select; double-click, Enter, F2, or type to edit when `allowDataEdit` is on; arrows / Tab move; Backspace clears. **Add row** appends a row. The sheet also keeps a trailing **Add row** row. Body cells are white on a neutral-secondary sheet; the selected column header fills solid selected-purple. Only the visible row window (plus overscan) is mounted; spacer rows keep the scrollbar honest, keyboard moves (including PageUp / PageDown) scroll the active cell into view, and an in-progress edit commits if its row scrolls out of the window. The Cards catalog is windowed the same way by card row (values are single-line with ellipsis + `title` so every card shares one height; the carousel shows one card).
- Clicking a column header opens the **CATEGORY ANALYSIS** dock (211px, beneath the stage): a `PanelHeader` whose left slot is an extra-small CADS `Dropdown` to switch columns and whose right slot is a close button. The body is two halves — title + **Numerical** / **Categorical** brand `Tag`, description, and four stat cards (Minimum / Maximum / Median / Range for numbers; Categories / Most common / Least common / Rows for categories) on the left; a **Distribution** bar list on the right that never exceeds five rows: categorical columns show the top four values plus a muted **Other (N more)** bucket whenever there are more than four, and numerical columns use `histogramBins`, which picks a "nice" bin width (1 / 2 / 2.5 / 5 × 10ⁿ, integer-only for whole-number columns) so the data fits in at most five bins with readable edges (`1 | 2–3 | 4–5 | 6`, `0–20 | 20–40 | …`). No predict/feature actions live here.
- Training lives in a 300px **TRAIN** rail (`TrainRail` in `DataStudio.tsx`) to the right of the sheet, hidden when the level hides Train or no dataset is loaded. It stacks bordered cards (no in-card eyebrow headers): **Train model** card (thick-labeled **Predict:** / **Using:** dropdowns with helper text, `Using` shows a check icon once features are picked and its checklist menu is synced to the trigger width via `useChecklistMenuWidth`; KNN's **k** is not a student control — studio searches it on the holdout, guided may lock `defaultKnnK`; footer holds a full-width small **Train model** primary button). **Cardinality guardrail:** a categorical label or feature with more than 50 distinct values swaps the dropdown helper text for an error ("Brand has 355 different values. Pick a column with 50 or fewer to predict." / "Stars has 51 different values (and 1 more). A feature can have at most 50.") and disables Train (the disabled tooltip repeats the reason); a label with more than 8 values gets a warning helper ("Country has 38 values, so the chart shows the most common ones and folds the rest into Other.") but still trains. Once a model exists the footer button becomes outlined **Rerun training** (`arrow-rotate-left`) and a **Results** card appears below (`aria-live`): **Accuracy** (success color) | **Number correct** `correct/total`, and a footer with **Scorecard** / **Save model** (per flags) plus the contained primary **Test model →** which jumps to Testing. Studio KNN still searches k on a holdout, but that split is not named in the student UI. The Train tooltip only appears while the button is disabled (it explains why).
- Header is the shared `PanelHeader` labeled **WORKSPACE**: left slot is a CADS `SegmentedButton` (`extraSmall`, same pattern as Web Lab) **Data Set** (`table`) | **Testing** (`flask`) when both tabs are on; a single-tab level hides the control. Testing is disabled until a model exists (hover tooltip: "Testing unlocks once a model is trained"). Right slot: two extra-small outlined secondary buttons — the **algorithm chip** (algorithm icon + name, `right-left` end icon; "Choose algorithm" before setup; disabled when `algorithmLock`) that opens the setup modal, and **Start over** (`arrow-rotate-left` + label). There is no header Model button — scorecard/save live in the two result surfaces below. **Test model →** on the Results card is hidden when Testing is off.
- **Test** is a dashboard: a 40px statement strip (**Predict** + large brand `Tag` for the label + **based on** + large success `Tag`s for the first two features and a `+N` overflow chip, all forced to 24px tall; dataset · `k=N` · **N% Accuracy** plus **Scorecard** / contained **Save model** on the right), visualization as the canvas, and an **Input → Output** dock: two equal-height cards (same `shape-md` bordered treatment as the Train rail, no eyebrows, no selected/brand tint) — "Try a prediction" (outlined secondary extra-small **shuffle** that fills every field with a random in-range value, then an extra-small icon-only `SegmentedButton` — Diagram/Rules or Target/`table` — — a category from `uniqueValues`, a number between the column min/max via `numericalStats`, integers stay integers; fields in an auto-fit grid; numeric placeholders still show "min 0.5, max 8.1") → arrow connector → an *Output* card titled with the label column. Output stays a plain card while inputs are missing ("2 more inputs") and after a prediction exists. Card titles ("Try a prediction", label column) are 14px `label-2`; the predicted value is `heading-h4`. KNN explanation is "{label} got the most votes among the {k} nearest rows."
- **Visualization frame** (`VizFrame`): every viz is a full-bleed `section` (no inset card, no radius). Test hides the frame toolbar — view tools live in the Try a prediction card header. Both algorithms overlay a shared **NavigatorCard** on the diagram / target view only (300px, `shape-md`, top-right of the canvas; hidden on Table and Rules): contained **Play** + Previous / Next chevrons, one dot per step (`aria-current="step"`, tooltip = step name), and a wrapping step statement (`**PetalLengthCm** is 5 → **> 2.5**`, `**Male** wins with 21 of 31 votes`). Play rewinds to step 1 and walks the rest at 1s per step (Prev / Next / dots cancel; `prefers-reduced-motion` only rewinds). Statements are the only prose in the frame: no hover tooltips on nodes, and wordless empty states (the card carries the single hint, "Fill in the inputs to trace your example."). A visually-hidden `aria-live="polite"` span announces each step change in full sentences. The card also takes an optional `detail` node that replaces the statement (with an `xmark` "Back to the trace" button) — the tree uses it for node details. A new prediction jumps to the last step.
- **Canvas Testing layout** (dev panel **Testing layout → Canvas**, `testLayout: "canvas"`; default is **Dock**): nothing is docked and nothing clips the viz. The dock footer and NavigatorCard go away; `TestDashboard` hands each viz a `canvasChrome` (`{ outcome, inputCard }`) and `CanvasCards` floats three things over a full-bleed viz — a small **trace toolbar** card top-left (`TraceBar orientation="toolbar"`: Play + Previous / dots / Next; hidden on Table and Rules), and a single 300px right-hand column with the vertical **Try a prediction** card (shuffle, then Target/Table or Diagram/Rules, stacked fields, scrolls inside) above the **prediction card** (14px `label-2` title, `heading-h4` predicted value or pending text, one-line explanation, then algorithm body: KNN vote tally + NEAREST NEIGHBORS + **See all rows →** / **Back to the target**; tree **PATH** list). The prediction card always shows the **end state** — stepping only animates the visualization, except the tree's PATH numbers, which fill selected-purple up to the current step (the current one gets a ring). Vizzes are never padded or clipped by the cards: the KNN target draws full-bleed (dots render under the cards) and centers its rings in the open strip via `insetRight={CARD_INSET}`; the tree stage is full-bleed and scrollable but its resting spot and scroll-into-view math treat the right `CARD_INSET` as covered. The decision tree switches to the **vertical** orientation (root at top, leaves in columns, edge labels centered above their node) so it grows away from the cards. On Table / Rules the same cards stay put and a train-rail column (secondary fill, left border, no header) appears behind them; the table fills the leftover sheet and does not run under the panel. `testLayout` is excluded from the session identity, so flipping the flag keeps the trained model.
- **Decision tree** (`DecisionTreeViz`): the stepper lives in the floating **NavigatorCard** (same card as KNN). **Diagram** view is a scrollable stage. Layout is "leaf-stack" left-to-right (top-to-bottom under the canvas layout — same algorithm on swapped axes, `laneGap` 24 / `levelGap` 72): each leaf takes one row, decision nodes center on their visible children, so nothing overlaps by construction and the stage grows instead of squeezing. Nodes come in two sizes (`treeLayout.ts` lays out per-node sizes, per-depth column widths, and variable row heights): **cards** (184×64: question title `Feature?` or predicted label swatch, a label-colored **distribution bar**, "N rows" / "N rows · P%") for nodes revealed by the trace so far, and compact muted **pills** (132×30: title or label swatch only) for everything else — so before a prediction the whole tree is pills, and a prediction turns its path into cards step by step. Edge labels (`≤ 3.5`, `chicken`) hug their text on the last stub of the connector, with a tight canvas-colored knockout so the line does not run through the letters (and does not cover the T-junction): filled selected-purple once taken, outlined for the branch about to be taken. Every node uses CADS `--shape-sm` (6px) — no mix of rounded pills and square cards. The diagram always shows the full tree; there is no expand/collapse. Diagram / Rules lives in the Try a prediction card header. With a prediction, path nodes/edges turn selected-purple, the current step's node gets a ring, and stepping scrolls the current node (and the question it came from, when both fit) into view without stealing focus. There are no hover tooltips: clicking or pressing Enter / Space on any node **selects** it (`aria-selected`, dark border) and shows its detail in the navigator card in place of the step statement — "Predicts ● yes · 100% of 3 rows" or "**Salsa?** · 8 rows · 2 branches" plus a small distribution bar and counts — dismissed with the `xmark`, Escape, a click on the stage, or stepping. **Accessibility:** the diagram is a real `role="tree"` — flat `treeitem`s with `aria-level` / `aria-setsize` / `aria-posinset` / `aria-current` / `aria-selected`, roving `tabindex`, and Arrow Up/Down (visible order), Right (first child), Left (parent), Home / End, Enter / Space (select), Escape (clear selection). Accessible names read like "Branch chicken. Question: Salsa? 8 rows, 3 no, 5 yes. On your example's path." The SVG links are `aria-hidden`. **Rules** view (replaces the old Outline) flattens the tree into a table with one row per leaf — # / **If** (feature + branch chips joined by "and") / **Then** (label swatch) / **Rows** (`N · P%` + bar); the rule your example matches is tinted, `aria-current`, tagged "Your example", and scrolled into view. It is the linear reading of the model for screen readers, small screens, or huge trees.
- **KNN** (`KnnViz`): two views (the old Scatter view is gone — it only ever showed two of N features and contradicted the ranking). **Distance target** (default): the plot centers in the leftover canvas beside the floating card (Table fills the leftover sheet beside a docked card column); your example sits at the center, every rendered row is a dot placed by its *actual* multi-feature distance (honest for any number of features), each label owns a wedge (labels orbit the panned center just outside the fit ring, "N rows" until the last step, then "N votes"), and your example is a purple bullseye (ghost bullseye when empty, no caption). When the label set is wider than the 8-color palette, `groupLabels` keeps the 6 labels with the most votes (then frequency) as named wedges and folds the rest into one neutral **Other (N more)** wedge, so a 38-country label still reads as 7 wedges instead of 38 slivers. The radial scale is **neighborhood-first**: the inner 62% of the radius covers 0…2× the k-th neighbor's distance and the rest compresses out to the farthest row, so the nearest rows are visibly nearest even on a 1000-row sheet; guide rings are labeled with their real distance (a tick that would land on the k-ring is skipped). On the last step, **spokes** run from the center to each voter, a dashed purple **k nearest** ring encloses them with numbered dots, and the wedges switch to vote counts. **Dense regime** (k > 30): spokes and numbered badges are dropped, the k-disc becomes a shaded solid ring, and each wedge gets one **vote arc** just outside the ring whose thickness is proportional to its share of the same k-nearest votes as the card's `VoteTally` (the winner's arc is bold) — hovering an arc opens a popover with the category name and `N of k votes`; rank badges appear only on hover. **Ties** at the k-th distance (common with categorical features) are shown honestly: tied rows are hollow dots on an amber band at that radius. **Semantic zoom:** rows are binned by (wedge, distance ring, angular sector) at the current zoom into count **bubbles** (radius grows with √count, capped at 18px; amber when the whole bin is tied). The cell size adapts to how many rows are drawn (`binSize`: 20px × √(rows/100), clamped 22–64px, so 400 rows bin at 40px and a 50-row sheet stays as dots); zooming in shrinks the cells in data space so bins split into smaller bubbles and finally individual dots. Hovering a bubble opens a BubbleCard ("4 rows · Taiwan · 2 away · 1 vote · Click to zoom in"); a press that does not travel more than 4px zooms 2.2× on it (handled in the frame's pointer up, because drag-to-pan captures the pointer and a plain `click` never reaches the bubble). Hover state is cleared whenever the viewport changes or the pointer leaves the frame, so a card cannot stay pinned to a mark that re-binned away; the k-ring, arcs, spokes, labels, and guides are `pointer-events: none` so the filled disc never blocks hover on the neighbors inside it. Ranked neighbors stay as individual dots (with badges) in the normal regime; the hovered rail row's dot is always pulled out of its bubble. The target **zooms and pans**: mouse wheel, drag (`grab` cursor), keyboard `+` / `-` / arrows / `0`, plus a floating tool stack (Zoom in / Zoom out / **Zoom to the neighbors** / Fit everything). Dot sizes stay constant under zoom; a new example resets to Fit. Same-label rows are spread around their wedge with a golden-ratio walk so equal distances do not stack. Only the closest 400 rows are drawn ("400 of 1000 rows shown"). **Table** lists your example pinned first, then the first 100 rows ranked by distance (first k marked as voters), each feature cell showing the row's value and ✓ match or Δ difference; its empty state is a single "Nothing to compare yet." The floating **NavigatorCard** is one 300px card with three KNN states. Shared chrome: Play + stepper, a lede (statement + metrics), a **NEAREST NEIGHBORS** list (3 preview rows), and a full-width **See all rows →** footer (disabled until there is a prediction). Head and footer stay pinned; the lede and neighbor list scroll when the card hits the canvas. **Place:** "**Your input is placed in the center**" + feature rows (name · dotted leader · value) + 3 dashed placeholder slots ("Neighbor Name"). **Measure:** "**Your nearest neighbors are mapped**" + the same `VoteTally` with muted senary fills + real neighbor rows (label title, `Row N · d away · n/N match`) with empty dashed badges. **Vote:** "**Male** wins with 21 of 31 votes" + colored tally + numbered label-colored 18px badges; Neighbor rows use a neutral-secondary fill on hover. **See all rows →** jumps to the Table. The card is Target-only in dock layout — Table is full-bleed. In canvas layout Table docks the card column like the Train rail (same 300px card geometry, no card shadows). The live announcement still uses `summarizeVotes` so it never runs past five labels. Hovering or focusing a neighbor highlights its dot and opens a **RowCard** (`role="tooltip"`) with per-feature deltas; hovering a dot does the reverse. Steps: Place your example → Measure distances → The k nearest vote. The Output card does not repeat the neighbor chips.
- `ModelActions.tsx` is the shared **Scorecard** / **Save model** button pair (Save model is the export entry point, `floppy-disk`) used by both the Data Results card footer and the Test metric strip. Each flag is independent: scorecard can be on with export off, and the reverse. `AiLabGuidedWorkspace` opens `ScorecardModal` or `ExportModal` via `onOpenModel(tab)`.
- **Scorecard** modal: every current row’s features / actual / prediction, mounted 200 rows at a time with a **Show 200 more rows** button (filter changes reset to the first page). Clicking a prediction jumps to Testing with those inputs when Testing is available.
- **Export** modal (**Save model**): model-card fields (name, intended use, limitations), session-local save, and a `getPrediction` snippet. Shown only when `showExport` is on.
- Start over confirms in a modal, clears training, and reopens setup if the student must choose again.
- Dev panel (AI Lab group) exposes the levelbuilder knobs, combinable except where a surface does not exist:
  - **Pre-set algorithm** — student chooses, or lock KNN / Decision Tree
  - **Pre-set dataset** — student chooses, or lock a catalog dataset (taco-truck presets appear on the guided/pretrained routes)
  - **Workspace tabs** — Data Set and Testing, **Data Set only** (hides Testing; combines with algorithm, dataset, train, edit, view), or **Testing only** (hides Data and Train; loads a pretrained model — Iris Species unless a dataset is pre-set)

  - **Show train panel** — TRAIN rail on Data Set. Off while Testing is still available loads a pretrained model so Testing is usable
  - **Allow editing data** — cell edit + Add row
  - **Default dataset view** — Table or Cards
  - **Show scorecard** — Scorecard modal
  - **Testing layout** — Dock vs Canvas (does not remount the session)

## Current Data Shape

- Studio catalog is every CSV in `src/data/ailab/datasets/*.csv` (build-time glob; currently Cats and dogs, drug200, Iris Species). The first catalog entry is the studio default. Seeded `tacoTruckDataset` and `tacoTruckGuidedDataset` remain for the pretrained and guided level presets only. **Testing only** in the Dev panel uses Iris Species (`iris_species`) unless a dataset is pre-set.
- `AiLabLevelConfig` mirrors production `mode` knobs used by Data Makes AI: algorithm lock, hide Dataset/Train/Testing, hide label select, optional pretrained model, `allowDataEdit`, `defaultDataView`. Studio adds `availableDatasets`, `lockDataset`, `requireDatasetChoice`, `showModelDetails`, `showExport`. Guided adds `classificationOnly` and `defaultKnnK`. `testLayout` (`"dock"` | `"canvas"`, default dock) picks the Testing chrome and is a dev-panel flag while the canvas layout is explored. `showExport` no longer implies the scorecard — they are independent modals. Dev panel mapping lives in `src/lib/aiLab/devConfig.ts`.
- Active `datasetId` is session state. Decision-tree training uses every current row and scores the whole sheet. Studio KNN reserves the last 10% as a holdout: k-search and reported accuracy share that split; live Test predictions exclude those rows from the neighbor pool. Guided KNN with `defaultKnnK` keeps leave-one-out on the sheet. `holdoutResults` is the scored list (holdout rows for studio KNN, every row otherwise).
- Training and prediction run locally in the browser, synchronously on the main thread (studio KNN holdout search on the 2,580-row ramen sheet is one distance ranking per holdout row, then a cheap vote per candidate k; the Train button's 420ms "Training…" pause still dominates). Export saves a model card in session memory and previews `getPrediction`; nothing is written to App Lab.

## Known Gaps

- No in-app CSV upload (CSVs are build-time via the drop folder) or side-by-side comparison of two saved models
- No A.I. bot train/test animation (the Train button only shows a short Training… pause)
- Save model (export) is a session-local model card + `getPrediction` snippet, not a real App Lab import
- Sheet columns are fixed-width, so wide datasets scroll horizontally beside the Train rail rather than flexing to fit like the Figma frames
- Tree trainer is a small canned-depth ID3 stand-in, not production `ml-cart` (depth sweep, regression). Guided tree nodes show sample count and impurity drop; they are not the full PM contribution tooltips
- KNN distance is not feature-scaled and the UI no longer says so (the rail footnote was cut for text budget); the Table's Δ columns are the only place a student can notice a large-range feature dominating
- Viz accessibility is designed in but not audited with a real screen reader: the tree has no type-ahead, the KNN target's individual dots are mouse-only (the rail, table, and live region carry the same information for keyboard users), the RowCard is `role="tooltip"` without `aria-describedby` wiring, the trace dots are buttons rather than a slider, and the tree's navigator-card detail is not announced when selection changes
- The KNN target draws the 400 nearest rows and hides the rest behind a note; zoom is manual (Fit by default, **Zoom to the neighbors** is a button) and the wedge spread is a golden-ratio walk, not a collision-avoiding layout. Exact-distance ties (all-categorical features) still land on one band — bubbles keep it legible, but a tied band of hundreds of rows is a ring of "2"/"3" bubbles, not individual dots, until you zoom
- The cardinality guardrail counts distinct values as typed (a blank cell is a value), so blank-heavy columns like ramen `Top Ten` count "" as a category and appear as an unnamed wedge/option. Shuffle skips blank category values so it still fills the field. The 8-label fold threshold is the palette size, not a tuned readability number
- The tree diagram always shows every node, so very wide categorical splits (dozens of branches) produce a tall stage that must be scrolled
- Spreadsheet has no sort, filter, fill-handle, or undo stack
- Training is still main-thread; a Web Worker would only matter for datasets an order of magnitude larger than the current drop folder. Column type inference is all-or-nothing (ramen `Stars` is categorical because of "Unrated"); a ≥95% numeric threshold is a pending data-quality follow-up
- Classic `AiLabWorkspace` / `GuidedDatasetPanel` pullback tables still render every row (they share the stats cache but are not virtualized)
- Studio KNN holdout is always the last 10% (deterministic), not a random split; guided KNN still scores the whole sheet
