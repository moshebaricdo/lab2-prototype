# AI Lab

## Purpose

Lab2 prototype of AI Lab. The student workspace is two experiences: **Data Set** (an immersive spreadsheet with a Train rail) and **Testing** (a prediction dashboard). There is no Train tab. Training lives in a right-hand **TRAIN** rail on Data Set. Lab2 Continue leaves the level.

Source intent: [PR #74600](https://github.com/code-dot-org/code-dot-org/pull/74600) (`ai-studio-prototype`) and the Data Makes AI handoff.

The **P0 handoff** (`/levels/ailab-p0`) is the curriculum-shaped demo: Bird / mammal / fish, Decision Tree, Predict locked to **Type**, Cards, training modal, auto-play, no edit / export / scorecard. The **Dev** panel on every AI Lab route mirrors the levelbuilder knobs (algorithm, dataset, label column, card title column, workspace tabs, hide train, default view, bundle wide splits). Canvas Testing is canonical. The **full studio** (`/levels/ailab`) stays the student-choice end state (scorecard + export + edit stay on via authored config, not Dev).

Classic three-tab chrome (`AiLabWorkspace` + Dataset / Train / Test) is still in the repo for pullback (`workspace="classic"`). Current routes use `AiLabGuidedWorkspace`.

It exports `knnDistances`, `neighborFeatureDeltas`, `knnVotes`, `majorityVote`, `summarizeVotes` (top-5 vote sentence with "and N others"), `classificationKCandidates`, and `regressionKnnK`. Studio trains KNN with a 10% end holdout: classification searches `{1, 3, 5, 7, 17, 31, 45, 61, √n}` (k = n when n ≤ 10; `n/3` was dropped because on signal-less features it "wins" the holdout by degenerating into a majority-class guesser with hundreds of neighbors); numeric labels skip the search (`k = 1` if n < 100, else `k = 5`) and score a prediction as correct when it is within 5% of the label column's range. ## CADS consumption

Workspace chrome uses packaged CADS via `Lab2Shell` → `CadsLabProvider`: `Button`, `Modal`, `Radio`, `Dropdown` (with `label` / `helperText`), `Tabs` (classic pullback rail), `TextInput`, `Tag`, `SegmentedButton` (incl. `iconOnly`; workspace header Data Set / Testing), `Tooltip`. Panel headers reuse the shared `PanelHeader` (`src/components/ui/PanelHeader.tsx`). Local SCSS uses unprefixed Foundations (`--background-*`, `--text-*`, `--shape-*`).

The workspace is full-bleed Lab2 chrome (header + tab rail + edge-to-edge panels), not the inset floating cards used by AI Chat Lab.

Visualizations are hand-rolled SVG + HTML rather than a graph editor, in the spirit of the [decision-tree POC](https://github.com/code-dot-org/code-dot-org/pull/75114): a left-to-right readable tree instead of a node-canvas. Production trains with `ml-cart`; this prototype still uses a local multi-way ID3-style trainer so categorical splits stay labeled as values (`salsa is hot`) instead of ordinal thresholds (`salsa < 0.5`).

- Decision Tree: HTML nodes (`role="tree"` / `treeitem`) positioned by `treeLayout.ts`; SVG under them draws only the connectors (`aria-hidden`). No visx.
- KNN: Target and Table views are plain SVG/HTML. No visx anywhere in the AI Lab viz folder.
- Both share `VizFrame` (canvas; Test owns the chrome strip), `NavigatorCard` + `TraceBar` (Play + stepper; floating card on both algorithms) — or `CanvasCards` + `TraceBar` under the `canvas` Testing layout — and the same label color order from `labelPalette.ts`, so the legend colors on the tree's distribution bars match the KNN dots.

## Current UX Behavior

- Resource panel: Instructions (swap by section), Continue, Dev. AI Tutor, Version History, and Backpack are off.
- Lands on **Data** unless the level hides that tab. One **setup modal** (CADS Modal, not stacked dialogs) collects dataset and algorithm in the same view. A locked/pre-selected side is omitted. Compact choice rows. Test stays locked until a model exists (or the level ships a pretrained model).
- **Intro activity** (`config.introActivity`, off by default — advanced levels land straight on the sheet): stands in for the sheet, hides the Train rail and view toggles, and ends with `lab.completeIntro()`. `info` opens the **dataset story** as a required modal (**Open the data**). `classify` opens the story first (**Let's try it**, `showStoryFirst` default on), then deals `rowCount` (default 5, or explicit `rowIndexes`) rows as one large card at a time: clue rows for every non-label column (or `visibleColumns`; `reveal: "one-at-a-time"` hides all but the first behind **Show another clue**), the label row hidden as a dashed brand **?**, and one button per label value (palette dot + name). Picking a value locks the row, turns the real answer green (check) and a wrong pick red (x), fades the rest, fills the label row, and shows "Right — this animal is a Bird." / "Not quite. This animal is a Fish." with **Next** / **Finish**. A summary ("You got N of M right… every card you saw is one row") ends on **Open the data**. Nothing here is dataset-specific: label values, clue columns, and rows all come from the sheet; `canClassify` requires a categorical label with 2–8 values (else the mode falls back to `info`). `introRowIndexes` walks label values round-robin so five cards never show five of the same answer.
- **Dataset story** (`dataset.story`: `rowNoun`, `whatIsARow`, `source`, `question`, optional `whyItMatters`, optional `imageColumn` reserved for a picture slot) is optional metadata on the dataset; `storyFor()` infers a plain one from the columns when absent. It renders as **About this data** — an `info` icon button after **N rows** in the dataset header opens a 520px modal: "52 animals · 5 columns", **What is one row?** + one real row as a small key / value card (label row tinted pink with a pink Tag), **Where it came from**, **The question** (+ "The answer for every animal is already in the **Type** column…"), **Why it matters**. Bird / mammal / fish, Cats and dogs, and Iris carry stories in `datasets/index.ts`.
- **Data Set** is a native spreadsheet by default (`defaultDataView: "cards"` lands on Cards instead). A 40px **dataset header** sits above the sheet: a **dataset chip** (extra-small outlined button with `right-left` when pickable; opens setup like the header algorithm chip) or plain **dataset name** (14px semibold primary text when locked) · **N rows** · **About this data** info button on the left; on the right an extra-small contained secondary **Add row** (`plus`, table only, hidden when `allowDataEdit` is false) · a labeled Table / Cards segmented control (plus Catalog / Carousel when Cards is active and `hideCardLayoutToggle` is off). Click a cell to select when editing is on; when `allowDataEdit` is false, cell clicks only open column analysis (no cell focus ring). Double-click, Enter, F2, or type to edit when `allowDataEdit` is on; arrows / Tab move; Backspace clears. **Add row** appends a row. The sheet also keeps a trailing **Add row** row. Body cells are white on a neutral-secondary sheet; the selected column header fills solid selected-purple. Only the visible row window (plus overscan) is mounted; spacer rows keep the scrollbar honest, keyboard moves (including PageUp / PageDown) scroll the active cell into view, and an in-progress edit commits if its row scrolls out of the window.
- **Cards** view (`DataCards` in `DataStudio.tsx`) opens as a **carousel** when the sheet has 24 or fewer rows and as a **catalog** otherwise (`defaultCardLayout` in `useAiLabState.ts`, re-evaluated on initial state, on Table → Cards, and on dataset swap; the Catalog / Carousel control still overrides it for the session). `hideCardLayoutToggle` hides that control and always uses the carousel. `cardTitleColumn` titles each card with that column's value (P0 uses Animal → "Hawk"); the pager still says **Row N of N**, and the title column is omitted from the card body. It is a scrolling stage over a sticky **pager footer** (`CardsFooter`: 1px top border + 8px padding around small 32px controls = 49px, the same box as the resource panel's Continue bar so the two footers share a baseline; pager centered). Card rows are read-only `dl` pairs — column names are plain text, not buttons — and the Cards view never opens the analysis dock. Label and feature columns color the name (accent pink / info) and add an 8px dot in that color after it (no row tint). On the carousel the role name is semibold and other names stay regular; catalog names stay semibold either way. Catalog card anatomy follows Figma AI Lab 2 `5383:6634`: 10px/12px padding, `shape-sm`, `body-2` semibold "Row N", then `body-3` semibold name / `body-3` regular value rows (both primary text, 16px apart) separated by 1px `border-neutral-primary` hairlines on a 6px rhythm. **Catalog** is paginated rather than virtualized: 8px stage padding and 8px grid gap, 24 cards per page by default, with a CADS `TablePagination` (`small`) in the footer — **Cards per page** dropdown (12 / 24 / 48 / 96 / 192), `1–24 of 200` range, prev / next. When the dataset fits the smallest page size (≤ 12 rows) the dropdown goes away and the footer uses the compact `PagerNav` (prev / `1–12 of 12` / next) instead. The grid's column count is measured from the stage width and snapped down to a divisor of 12 (`1, 2, 3, 4, 6, 12`), so every page size ends on a complete row at any width. Values are single-line with ellipsis + `title` so cards in a grid row share a height; page changes scroll the stage back to the top and the page resets when the dataset changes. **Carousel** shows one row as the top card of a **deck**: a 520px-max featured card centered on the stage (`body-1` semibold heading, `body-2` names and values, `shape-lg`, `elevation-sm`, 16px top padding and 6px bottom so the last row's padding meets the mock inset) with up to two **empty** cards peeking out above it — shells with the same border, radius, and shadow, no row contents — one per remaining row, so the last row has none. The deck renders a window of rows (previous, active, two behind, one hidden on-deck) as slots sharing one grid cell; each slot's transform / opacity / z-index is a function of its depth from the active index (`--deck-depth`: −12px and −3.5% scale per step), and because slots are keyed by row index a flip only changes depths, so one 280ms `cubic-bezier(0.32, 0.72, 0, 1)` transition moves the whole stack: the top card deals off toward the viewer (`+28px`, fades), everything behind steps forward, and the on-deck card fades in at the back — Previous plays it in reverse. No entrance animation on load; `prefers-reduced-motion` drops the transition. The footer uses the same `PagerNav` — prev / **Row N of N** (`aria-live`) / next small icon buttons built from CADS `Button`; the stage is focusable and Arrow keys / Home / End flip cards.
- Clicking a column header opens the **COLUMN ANALYSIS** dock (the left summary sets the height — a heading, one-line description, and the stat cards is the 186px Figma frame; beneath the stage): a `PanelHeader` labeled **COLUMN ANALYSIS** with a close button on the right. Switch columns by clicking a different header in the sheet. The body is two halves — column name, optional author `description`, and stat cards on the left. Cards always lead with **Type** (Categorical or Numerical). Categorical: **Normal** (repeats exist) shows Type / Values / Most Common / Least Common; **all unique** or **single value** shows Type / Values only (two-card row). A column with more than 50 values also shows a warning: it cannot be the label or a feature. Numerical: Type / Minimum / Maximum / Range. On the right, a **Distribution** vertical bar chart (`ColumnDistributionChart`, visx). The chart fills the right column, so a wrapped description or the cardinality warning grows the panel and the chart with it, and the x-axis labels meet the stat cards. Categorical columns draw one bar per value only when there are 5 or fewer; wider columns replace the chart with **Too many values** ("A graph is shown when there are 5 or fewer values."). Numerical columns keep `histogramBins`, which picks a "nice" bin width (1 / 2 / 2.5 / 5 × 10ⁿ, integer-only for whole-number columns) so the data fits in at most five bins with readable edges (`1 | 2–3 | 4–5 | 6`, `0–20 | 20–40 | …`) — the mocks leave this pane empty, and the prototype keeps the graph. Bar fills reuse the Testing label palette (`labelPalette.ts`: natural-sort `uniqueValues` order), with `--shape-md` (6px) rounding; counts appear in a hover tooltip (swatch + label + value), never on the bars. No predict/feature actions live here.
- Training lives in a 280px **TRAIN** rail (`TrainRail` in `DataStudio.tsx`) to the right of the sheet, hidden when the level hides Train or no dataset is loaded. It stacks bordered cards (no in-card eyebrow headers): **Train model** card (thick-labeled **Predict:** / **Using:** dropdowns with helper text — "What you want your model to predict" / "What your model predicts using" — `Using` shows a check icon once features are picked and its checklist menu is synced to the trigger width via `useChecklistMenuWidth`; KNN's **k** is not a student control — studio searches it on the holdout, guided may lock `defaultKnnK`). **Cardinality guardrail:** a categorical label or feature with more than 50 distinct values swaps the dropdown helper text for an error ("Brand has 355 different values. Pick a column with 50 or fewer to predict." / "Stars has 51 different values (and 1 more). A feature can have at most 50.") and disables Train (the disabled tooltip repeats the reason); a label with more than 8 values gets a warning helper ("Country has 38 values, so the chart shows the most common ones and folds the rest into Other.") but still trains. A live **statement sentence** (`PredictionStatement`) sits in its own top-bordered band under the dropdowns — **Predict** [pink Tag] **based on** [info Tags] in `label-3` with CADS **small** Tags (20px tall, label overridden to 12px). The modal keeps the larger `label-2` sentence and a 24px chip (`.tag`); the Testing strip still uses that 24px pin. Dashed placeholder Tags ("a column", "one or more columns") until each side is chosen — same `--shape-sm` Tag geometry as a filled chip, `background-neutral-primary` fill, dashed `border-neutral-secondary`. The same colors tint the **sheet**. Label headers are accent-pink mid with a pink primary border; feature headers are info mid with an info primary border; body cells are the matching light fill at 50% (`border-accent-pink-light` / `border-info-light`) and go solid on row hover. An ordinary row hover is neutral-secondary at 50%. Clicking a highlighted header only fills that header selected-purple — body cells keep their role tint. A focused cell rings in brand, pink, or info to match its role. Cards mark the same roles with a colored name and dot. Footer holds a full-width small **Train model** primary button until a matching decision-tree model exists — then the footer hides and **Replay training** is an outlined secondary play button on the Results mini-map. A stale or KNN model keeps outlined **Rerun training** (`arrow-rotate-left`) in the footer. A **Results** card appears below (`aria-live`): for a decision tree, an 80px **mini-map** (`TreeThumbnail`: link strokes + blocks, leaves in label colors, no text; an outlined secondary play button in the corner replays training when the tree still matches); then **Accuracy** (success color) | **Number correct** `correct/total`, and a footer with **Scorecard** / **Save model** (per flags) plus the contained primary **Test model** (`arrow-right`) which jumps to Testing. Studio KNN still searches k on a holdout, but that split is not named in the student UI. The Train tooltip only appears while the button is disabled (it explains why).
- **Training modal** (`trainingModal`, default on; decision tree only — KNN keeps the 420ms inline "Training…" pause): **Train model** trains immediately and opens a 760px CADS Modal titled **Training your model**. The large statement sentence sits in the body above the tree. A status line narrates while the tree grows ("Sorting 52 animals into groups by asking questions about Has feathers and Breathes with lungs…" → "Checking each group's guess against the real Type…") and then yields to the results row. `TreeGrowth` draws the tree top-down at card size, one node every 650ms in depth order (node fades in from above, its connector and edge-label pill with it, its distribution bar fills left to right; every node uses `border-neutral-secondary`); after the last node, every leaf pops a **✓ N** success pill and, when nonzero, an **✗ N** error pill (`leafScore`: rows whose real label is not the leaf's prediction); then the results row fades in (Accuracy | Number correct | one-sentence explanation of boxes / bars / wrong marks). Footer is **Skip** while growing (jumps to the end), then **Back to data** (closes, Results card gains the mini-map) and **Test model** with an `arrow-right` icon. The tree scales to fit the modal width and a 420px height cap so it is always fully visible. **Replay training** on the Train card reopens the same modal from step 0. `prefers-reduced-motion` lands on the finished state.

## Known Gaps

- No in-app CSV upload (CSVs are build-time via the drop folder) or side-by-side comparison of two saved models
- Training animation exists for the decision tree only (training modal); KNN still shows the short Training… pause and has no rows-placed-then-vote walk. The training modal has no deck → sheet transition (the classify deck hands off with a plain swap) and no picture slot yet (`story.imageColumn` is reserved, unused)
- The **sort and quiz** animation is a dev-flag experiment, not yet the default: its Testing phase replays predictions on the same rows the tree trained on (the tree has no holdout), it quizzes 3 rows rather than rolling every row, trees wider than ~4 leaves scale the stage down (dots shrink with it), and neither variant has been playtested against the other
- Vocabulary pass across the older routes' instructions is pending; only the v2 playtest copy uses the row / column / predict-based-on vocabulary consistently
- Save model (export) is a session-local model card + `getPrediction` snippet, not a real App Lab import
- Sheet columns are fixed-width, so wide datasets scroll horizontally beside the Train rail rather than flexing to fit like the Figma frames
- Tree trainer is a small canned-depth ID3 stand-in, not production `ml-cart` (depth sweep, regression). Guided tree nodes show sample count and impurity drop; they are not the full PM contribution tooltips
- KNN distance is not feature-scaled and the UI no longer says so (the rail footnote was cut for text budget); the Table's Δ columns are the only place a student can notice a large-range feature dominating
- Viz accessibility is designed in but not audited with a real screen reader: the tree has no type-ahead, the KNN target's individual dots are mouse-only (the rail, table, and live region carry the same information for keyboard users), the RowCard is `role="tooltip"` without `aria-describedby` wiring, the trace dots are buttons rather than a slider, and opening a tree node in place is not announced beyond `aria-selected` (the detail text is in the node's accessible name only after re-reading it)
- The KNN target draws the 400 nearest rows and hides the rest behind a note; zoom is manual (Fit by default, **Zoom to the neighbors** is a button) and the wedge spread is a golden-ratio walk, not a collision-avoiding layout. Exact-distance ties (all-categorical features) still land on one band — bubbles keep it legible, but a tied band of hundreds of rows is a ring of "2"/"3" bubbles, not individual dots, until you zoom
- The cardinality guardrail counts distinct values as typed (a blank cell is a value), so blank-heavy columns like ramen `Top Ten` count "" as a category and appear as an unnamed wedge/option. Shuffle skips blank category values so it still fills the field. The 8-label fold threshold is the palette size, not a tuned readability number
- With bundling off (the default), very wide categorical splits (dozens of branches) produce a stage that Fit shrinks to the 0.25× floor (illegible) and that must be zoomed and panned to read; Fit centers an overflowing tree rather than aligning the root. Bundling is behind a dev flag until playtests say whether the wall of pills is a learning moment worth keeping; an open bundle has no per-bundle close affordance (click the canvas), and bundle members are not summarized in the Train rail
- Opening a node in place reflows its siblings, so the tree shifts a little on select; the canvas pans to keep the opened card visible but does not animate the reflow itself
- Spreadsheet has no sort, filter, fill-handle, or undo stack
- Training is still main-thread; a Web Worker would only matter for datasets an order of magnitude larger than the current drop folder. Column type inference is all-or-nothing (ramen `Stars` is categorical because of "Unrated"); a ≥95% numeric threshold is a pending data-quality follow-up
- Classic `AiLabWorkspace` / `GuidedDatasetPanel` pullback tables still render every row (they share the stats cache but are not virtualized)
- Studio KNN holdout is always the last 10% (deterministic), not a random split; guided KNN still scores the whole sheet
- Playtest leftover (on purpose): KNN, other datasets, cell edit, and Save model stay locked. Dev panel can still remount those knobs. Auto-pretrain on Bird / mammal / fish without a feature list still picks **Animal** — Level 2 ships an explicit feature list so that does not happen in the stagger
