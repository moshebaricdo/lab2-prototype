# AI Lab

## Purpose

Lab2 prototype of AI Lab. The student workspace is two experiences: **Data Set** (an immersive spreadsheet with a Train rail) and **Testing** (a prediction dashboard). There is no Train tab. Training lives in a right-hand **TRAIN** rail on Data Set. Lab2 Continue leaves the level.

Source intent: [PR #74600](https://github.com/code-dot-org/code-dot-org/pull/74600) (`ai-studio-prototype`) and the Data Makes AI handoff.

The **full studio** (`/levels/ailab`) is the end-state prototype: student-chosen dataset and algorithm, scorecard, and export. Levelbuilder knobs (algorithm, dataset, tabs, train, export, sheet edit, default view) are all wired through the **Dev** panel on every AI Lab route so the same chrome can demonstrate guided, curriculum, and standalone-project shapes without extra routes.

Classic three-tab chrome (`AiLabWorkspace` + Dataset / Train / Test) is still in the repo for pullback (`workspace="classic"`). Current routes use `AiLabGuidedWorkspace`.

It exports `knnDistances`, `neighborFeatureDeltas`, `knnVotes`, `majorityVote`, `summarizeVotes` (top-5 vote sentence with "and N others"), `classificationKCandidates`, and `regressionKnnK`. Studio trains KNN with a 10% end holdout: classification searches `{1, 3, 5, 7, 17, 31, 45, 61, √n}` (k = n when n ≤ 10; `n/3` was dropped because on signal-less features it "wins" the holdout by degenerating into a majority-class guesser with hundreds of neighbors); numeric labels skip the search (`k = 1` if n < 100, else `k = 5`) and score a prediction as correct when it is within 5% of the label column's range. ## CADS consumption

Workspace chrome uses packaged CADS via `Lab2Shell` → `CadsLabProvider`: `Button`, `Modal`, `Radio`, `Dropdown` (with `label` / `helperText`), `Tabs` (classic pullback rail), `TextInput`, `Tag`, `SegmentedButton` (incl. `iconOnly`; workspace header Data Set / Testing), `Tooltip`. Panel headers reuse the shared `PanelHeader` (`src/components/ui/PanelHeader.tsx`). Local SCSS uses unprefixed Foundations (`--background-*`, `--text-*`, `--shape-*`).

The workspace is full-bleed Lab2 chrome (header + tab rail + edge-to-edge panels), not the inset floating cards used by AI Chat Lab.

Visualizations are hand-rolled SVG + HTML rather than a graph editor, in the spirit of the [decision-tree POC](https://github.com/code-dot-org/code-dot-org/pull/75114): a left-to-right readable tree instead of a node-canvas. Production trains with `ml-cart`; this prototype still uses a local multi-way ID3-style trainer so categorical splits stay labeled as values (`salsa is hot`) instead of ordinal thresholds (`salsa < 0.5`).

- Decision Tree: HTML nodes (`role="tree"` / `treeitem`) positioned by `treeLayout.ts`; SVG under them draws only the connectors (`aria-hidden`). No visx.
- KNN: Target and Table views are plain SVG/HTML. No visx anywhere in the AI Lab viz folder.
- Both share `VizFrame` (canvas; Test owns the chrome strip), `NavigatorCard` + `TraceBar` (Play + stepper; floating card on both algorithms) — or `CanvasCards` + `TraceBar` under the `canvas` Testing layout — and the same label color order from `labelPalette.ts`, so the legend colors on the tree's distribution bars match the KNN dots.

## Current UX Behavior

- Resource panel: Instructions (swap by section), Continue, Dev. AI Tutor, Version History, and Backpack are off.
- Lands on **Data** unless the level hides that tab. One **setup modal** (CADS Modal, not stacked dialogs) collects dataset and algorithm in the same view. A locked/pre-selected side is omitted. Compact choice rows. Test stays locked until a model exists (or the level ships a pretrained model).
- **Data Set** is a native spreadsheet by default (`defaultDataView: "cards"` lands on Cards instead). A 40px **dataset header** sits above the sheet: a **dataset chip** (extra-small outlined button with `right-left` when pickable; opens setup like the header algorithm chip) or plain **dataset name** (14px semibold primary text when locked) · **N rows** on the left; on the right an extra-small contained secondary **Add row** (`plus`, table only, hidden when `allowDataEdit` is false) · a labeled Table / Cards segmented control (plus catalog / carousel when Cards is active). Click a cell to select when editing is on; when `allowDataEdit` is false, cell clicks only open column analysis (no cell focus ring). Double-click, Enter, F2, or type to edit when `allowDataEdit` is on; arrows / Tab move; Backspace clears. **Add row** appends a row. The sheet also keeps a trailing **Add row** row. Body cells are white on a neutral-secondary sheet; the selected column header fills solid selected-purple. Only the visible row window (plus overscan) is mounted; spacer rows keep the scrollbar honest, keyboard moves (including PageUp / PageDown) scroll the active cell into view, and an in-progress edit commits if its row scrolls out of the window.
- **Cards** view (`DataCards` in `DataStudio.tsx`) opens as a **carousel** when the sheet has 24 or fewer rows and as a **catalog** otherwise (`defaultCardLayout` in `useAiLabState.ts`, re-evaluated on initial state, on Table → Cards, and on dataset swap; the Catalog / Carousel control still overrides it for the session). It is a scrolling stage over a sticky **pager footer** (`CardsFooter`: 1px top border + 8px padding around small 32px controls = 49px, the same box as the resource panel's Continue bar so the two footers share a baseline; pager centered). Card rows are read-only `dl` pairs — column names are plain text, not buttons — and the Cards view never opens the analysis dock. Catalog card anatomy follows Figma AI Lab 2 `5383:6634`: 10px/12px padding, `shape-sm`, `body-2` semibold "Row N", then `body-3` semibold name / `body-3` regular value rows (both primary text, 16px apart) separated by 1px `border-neutral-primary` hairlines on a 6px rhythm. **Catalog** is paginated rather than virtualized: 8px stage padding and 8px grid gap, 24 cards per page by default, with a CADS `TablePagination` (`small`) in the footer — **Cards per page** dropdown (12 / 24 / 48 / 96 / 192), `1–24 of 200` range, prev / next. When the dataset fits the smallest page size (≤ 12 rows) the dropdown goes away and the footer uses the compact `PagerNav` (prev / `1–12 of 12` / next) instead. The grid's column count is measured from the stage width and snapped down to a divisor of 12 (`1, 2, 3, 4, 6, 12`), so every page size ends on a complete row at any width. Values are single-line with ellipsis + `title` so cards in a grid row share a height; page changes scroll the stage back to the top and the page resets when the dataset changes. **Carousel** shows one row as the top card of a **deck**: a 520px-max featured card centered on the stage (`heading-h5` "Row N", `label-1` names / `body-1` values separated by hairlines, `shape-lg`, `elevation-sm`) with up to two real cards peeking out above it — one per remaining row, so the last row has none. The deck renders a window of rows (previous, active, two behind, one hidden on-deck) as slots sharing one grid cell; each slot's transform / opacity / z-index is a function of its depth from the active index (`--deck-depth`: −12px and −3.5% scale per step), and because slots are keyed by row index a flip only changes depths, so one 280ms `cubic-bezier(0.32, 0.72, 0, 1)` transition moves the whole stack: the top card deals off toward the viewer (`+28px`, fades), everything behind steps forward, and the on-deck card fades in at the back — Previous plays it in reverse. No entrance animation on load; `prefers-reduced-motion` drops the transition. The footer uses the same `PagerNav` — prev / **Row N of N** (`aria-live`) / next small icon buttons built from CADS `Button`; the stage is focusable and Arrow keys / Home / End flip cards.
- Clicking a column header opens the **COLUMN ANALYSIS** dock (min 211px tall, grows with the left summary; beneath the stage): a `PanelHeader` labeled **COLUMN ANALYSIS** with a close button on the right. Switch columns by clicking a different header in the sheet. The body is two halves — column name, optional author `description`, and stat cards on the left. Cards always lead with **Type** (Categorical or Numerical). Categorical: **Normal** (repeats exist) shows Type / Categories / Most common / Least common; **all unique** or **single value** shows Type / Categories only (two-card row). Numerical: Type / Minimum / Maximum / Median. On the right, a **Distribution** vertical bar chart (`ColumnDistributionChart`, visx) that never exceeds five bars: categorical columns show the top four values plus a muted **Other (N more)** bucket whenever there are more than four, and numerical columns use `histogramBins`, which picks a "nice" bin width (1 / 2 / 2.5 / 5 × 10ⁿ, integer-only for whole-number columns) so the data fits in at most five bins with readable edges (`1 | 2–3 | 4–5 | 6`, `0–20 | 20–40 | …`). Bar fills reuse the Testing label palette (`labelPalette.ts`: natural-sort `uniqueValues` order, neutral for **Other**), with `--shape-md` (6px) rounding; counts appear in a hover tooltip (swatch + label + value), never on the bars. No predict/feature actions live here.
- Training lives in a 300px **TRAIN** rail (`TrainRail` in `DataStudio.tsx`) to the right of the sheet, hidden when the level hides Train or no dataset is loaded. It stacks bordered cards (no in-card eyebrow headers): **Train model** card (thick-labeled **Predict:** / **Using:** dropdowns with helper text, `Using` shows a check icon once features are picked and its checklist menu is synced to the trigger width via `useChecklistMenuWidth`; KNN's **k** is not a student control — studio searches it on the holdout, guided may lock `defaultKnnK`; footer holds a full-width small **Train model** primary button). **Cardinality guardrail:** a categorical label or feature with more than 50 distinct values swaps the dropdown helper text for an error ("Brand has 355 different values. Pick a column with 50 or fewer to predict." / "Stars has 51 different values (and 1 more). A feature can have at most 50.") and disables Train (the disabled tooltip repeats the reason); a label with more than 8 values gets a warning helper ("Country has 38 values, so the chart shows the most common ones and folds the rest into Other.") but still trains. Once a model exists the footer button becomes outlined **Rerun training** (`arrow-rotate-left`) and a **Results** card appears below (`aria-live`): **Accuracy** (success color) | **Number correct** `correct/total`, and a footer with **Scorecard** / **Save model** (per flags) plus the contained primary **Test model →** which jumps to Testing. Studio KNN still searches k on a holdout, but that split is not named in the student UI. The Train tooltip only appears while the button is disabled (it explains why).
- Header is the shared `PanelHeader` labeled **WORKSPACE**: left slot is a CADS `SegmentedButton` (`extraSmall`, same pattern as Web Lab) **Data Set** (`table`) | **Testing** (`flask`) when both tabs are on; a single-tab level hides the control. Testing is disabled until a model exists (hover tooltip: "Testing unlocks once a model is trained"). Right slot: the **algorithm chip** (extra-small outlined button: algorithm icon + name + `right-left`; opens setup) when the student can change algorithm; hidden when `algorithmLock` is on. There is no header Model button — scorecard/save live in the two result surfaces below. **Test model →** on the Results card is hidden when Testing is off.
- **Test** is a dashboard: a 40px statement strip (**Predict** + large brand `Tag` for the label + **based on** + large success `Tag`s for as many features as fit on one line (never wrap — extra features collapse into a `+N` chip with a tooltip listing the overflow), all forced to 24px tall; dataset name (truncates with ellipsis when the strip is tight; full name in a tooltip) · `k=N` · **N% Accuracy** plus **Scorecard** / contained **Save model** on the right), visualization as the canvas, and prediction chrome — **canvas** by default (**Canvas Testing layout** below), or in **dock** layout an **Input → Output** footer: two equal-height cards (same `shape-md` bordered treatment as the Train rail, no eyebrows, no selected/brand tint) — "Try a prediction" (outlined secondary extra-small **shuffle** that fills every field with a random in-range value, then an extra-small icon-only `SegmentedButton` — Diagram/Rules or Target/`table` — — a category from `uniqueValues`, a number between the column min/max via `numericalStats`, integers stay integers; fields in an auto-fit grid; numeric placeholders still show "min 0.5, max 8.1") → arrow connector → an *Output* card titled with the label column. Output stays a plain card while inputs are missing ("2 more inputs") and after a prediction exists. Card titles ("Try a prediction", label column) are 14px `label-2`; the predicted value is `heading-h4`. KNN explanation is "{label} got the most votes among the {k} nearest rows."
- **Visualization frame** (`VizFrame`): every viz is a full-bleed `section` (no inset card, no radius). Test hides the frame toolbar — view tools live in the Try a prediction card header. In **dock** layout both algorithms overlay a shared **NavigatorCard** on the diagram / target view only (300px, `shape-md`, top-right of the canvas; hidden on Table and Rules): contained **Play** + Previous / Next chevrons, one dot per step (`aria-current="step"`, tooltip = step name), and a wrapping step statement (`**PetalLengthCm** is 5 → **> 2.5**`, `**Male** wins with 21 of 31 votes`). Play rewinds to step 1 and walks the rest at 1s per step (Prev / Next / dots cancel; `prefers-reduced-motion` only rewinds). Statements are the only prose in the frame: no hover tooltips on nodes, and wordless empty states (the card carries the single hint, "Fill in the inputs to trace your example."). A visually-hidden `aria-live="polite"` span announces each step change in full sentences. A new prediction jumps to the last step. (The card no longer has a node-detail slot — the tree opens node details in place on the canvas.)
- **Canvas Testing layout** (default; dev panel **Testing layout → Canvas**, `testLayout: "canvas"`): nothing is docked and nothing clips the viz. The dock footer and NavigatorCard go away; `TestDashboard` hands each viz a `canvasChrome` (`{ outcome, inputCard }`) and `CanvasCards` floats three things over a full-bleed viz — a small **trace toolbar** card top-left (`TraceBar orientation="toolbar"`: Play + Previous / dots / Next; hidden on Table and Rules), and a single 300px right-hand column with the vertical **Try a prediction** card (shuffle, then Target/Table or Diagram/Rules, stacked fields, scrolls inside) above the **prediction card** (`body-3-semibold` title; `heading-h6` predicted value; while inputs are missing the value is omitted and the card carries only "Fill in the inputs above to get a prediction." / "Fill in N more inputs above…" — `CanvasOutcome.value` and `.copy` are both optional; then algorithm body: KNN keeps its one-line explanation, vote tally + NEAREST NEIGHBORS + **See all rows →** / **Back to the target**; the tree drops the explanation sentence and renders its **path list** inline in the lede via `inlineBody`, no divider and no eyebrow). The prediction card always shows the **end state** — stepping only animates the visualization, except the tree's path stepper: 18px neutral-secondary badges (`body-4-bold` tertiary numbers) joined by a 1px hairline rail with 6px between rows; the question Play is on gets a ring, never a bigger size or a fill, so rows keep their height (the answer row never rings — it is the resting state); the last row is a selected-purple `flag` badge reading **AI predicts ● Mammal** (10px label dot + semibold label). Statements are `body-3`: `Has feathers is **no**` (feature regular, value semibold), collapsing `X is V → V` to `X is V` for categorical splits and keeping the arrow (an FA `arrow-right` icon, not a glyph) only when the branch differs from the value, e.g. `Spice level is 5 → **≤ 8.5**`. Vizzes are never padded or clipped by the cards: the KNN target draws full-bleed (dots render under the cards) and centers its rings in the open strip via `insetRight={CARD_INSET}`; the tree canvas is full-bleed and pannable but its Fit, Zoom to your path, and pan-into-view math treat the right `CARD_INSET` as covered. The decision tree switches to the **vertical** orientation (root at top, leaves in columns, edge labels centered above their node) so it grows away from the cards. On Table / Rules the same cards stay put and a train-rail column (secondary fill, left border, no header) appears behind them; the table fills the leftover sheet and does not run under the panel. `testLayout` is excluded from the session identity, so flipping the flag keeps the trained model.
- **Decision tree** (`DecisionTreeViz`): the stepper lives in the floating **NavigatorCard** (same card as KNN). **Diagram** view is a **pannable, zoomable canvas** with the same controls as the KNN target: the stage is laid out at its natural size inside an `overflow: clip` frame, panned with a `translate` on an outer element and zoomed with CSS `zoom` on an inner one (`zoom` re-lays out text and strokes at the new scale, so the tree stays crisp like the KNN SVG; `scale()` upsampled a rasterized layer and looked grainy — note `getBoundingClientRect` inside `zoom`ed content is unreliable in older Chromium, so all viewport math uses layout coordinates, never DOM rects); mouse wheel zooms about the cursor (0.25×–2.5×), drag anywhere pans (`grab` cursor; a press that travels past 4px captures the pointer so it never clicks the node it started on), keyboard `+` / `-` / `0` zoom and fit from anywhere in the frame, and arrows pan only when the frame itself is focused (inside the tree they still move between nodes). A floating tool stack bottom-left offers Zoom in / Zoom out / **Zoom to your path** (fits the revealed nodes; disabled with no trace) / Fit everything (disabled while at fit). Fit fills the open strip left of the canvas cards (`CARD_INSET`) but never enlarges past 1:1 (`MAX_FIT_ZOOM`) — the 14px node titles are already sized to read, and a three-leaf tree should not become a poster; a new tree starts at Fit. Fit and the path frame center on the **visible node extents** (`unionBox` of node boxes), not the layout box, which carries a trailing lane gap on one side and would sit the nodes ~12px off-center. The view has a **follow** mode (`"fit"` | `"path"` | `null`): while following, Fit (or the path frame) is re-applied whenever the frame resizes or the layout reflows — sidebar drag, a node opening in place, a bundle unfolding — so the tree stays centered; any manual wheel, drag, keyboard pan, or zoom button lets go, and the Fit / Zoom to your path buttons re-arm it. A **new prediction recenters** (the path turning into cards grows the stage): it arms `fit` when the whole tree stays legible at fit (`LEGIBLE_FIT_ZOOM` 0.5), otherwise `path` (the full path, not the revealed prefix, so the step index catching up cannot half-frame it); clearing the inputs recenters too. Same prediction twice does not move the view. Programmatic moves glide (240ms, off under `prefers-reduced-motion`); wheel and drag track the pointer directly. Layout is "leaf-stack" left-to-right (top-to-bottom under the canvas layout — same algorithm on swapped axes, `laneGap` 24 / `levelGap` 72): each leaf takes one row, decision nodes center on their visible children, so nothing overlaps by construction and the stage grows instead of squeezing. Nodes come in three sizes (`treeLayout.ts` lays out per-node sizes, per-depth column widths, and variable row heights; `layoutTree` takes a `measure(node, size)` so the detail height can depend on the node) and are all the same white card with a **2px border** (`border-neutral-secondary`; `border-selected-primary` on the traced path), `shape-sm`, `shadow-sm` (`shadow-md` on hover and when opened, back to `shadow-sm` on press with a neutral-secondary fill): **pills** (200×44: `body-3-semibold` title `Feature?` or a 12px label dot + label, plus "N Rows" in `body-4` tertiary on the right) for everything the example did not pass through, **cards** (200×60: the pill plus a 6px label-colored **distribution bar**) for nodes revealed by the trace so far, and one **detail** card (same 200 width so opening never shifts siblings sideways; height summed from its rows and an estimated 1–3 note lines by `detailDimensions` — the paddings in `.nodeDetail` are load-bearing) for the node the student opened — so before a prediction the whole tree is pills, and a prediction turns its path into cards step by step. Edge labels (`≤ 3.5`, `chicken`) are 22px `body-4` pills (`neutral-secondary` fill, which reads as plain text on the matching canvas by design; `EDGE_LABEL_HEIGHT` / `EDGE_LABEL_GAP` in the viz mirror the CSS) sitting on the last stub of the connector so the line does not run through the letters: filled selected-purple with `text-selected-primary` semibold text once taken, outlined for the branch about to be taken. The diagram always shows the full tree; there is no per-branch collapse (see **Bundle wide tree splits** below for the one exception). Diagram / Rules lives in the Try a prediction card header. With a prediction, path nodes/edges turn selected-purple (the current node carries `aria-current="step"` but no ring — the card border is the whole state), and stepping pans the current node (and the question it came from, when both fit at the current zoom) into the open strip without stealing focus or changing zoom; keyboard focus moves do the same. There are no hover tooltips or popovers: clicking or pressing Enter / Space on any node **opens it in place** (`aria-selected`, `shadow-md`) — `sizeOf` returns `detail` for the selected key, so the node grows into the detail card (title row, then one 18px row per present label: label · proportion track · semibold count; a leaf adds a hairline rule and the two-line note "4 of 5 examples here are Mammal, so this predicts Mammal." — a bundle says "8 branches (Dog, Cat, …) all predict Mammal.") and its siblings reflow around it; the canvas pans just enough to keep the opened card in the open strip. Clicking it again, Escape, a click on the empty canvas, or stepping closes it. The prediction card is untouched by selection — it only ever shows the end state.

  **Bundle wide tree splits** (dev panel, `bundleWideSplits`, default **off** — an experiment to gauge whether a wide categorical split should stay a visible "wall of pills" learning moment): when a decision node has **7+ branches** (`BUNDLE_MIN_BRANCHES`), its leaf children that predict the same label fold into one **bundle** node per outcome — a dashed pill "● Bird ×8" with the edge label "8 branches" (`treeLayout.ts` `drawnBranches`; the bundle is a synthetic leaf whose `labelCounts` / `sampleCount` are the members' sums, key `bundleKey(parentKey, prediction)`, and `LaidOutNode.bundle` lists the members). Bundles are placed where their first member sat so sibling order holds. A bundle **auto-opens** while the traced path runs through one of its members (checked against the whole `pathKeys`, not the revealed prefix, so stepping never reflows the group mid-trace): predicting Bat unfolds the eight mammals with Bat lit among Dog, Cat, Horse… while `Bird ×8` and `Fish ×8` stay folded, and predicting Trout folds Mammal and opens Fish. The taken leaf is never pulled out of its group as a lone node. Click / Enter on a bundle **opens** it manually (members drawn individually; `aria-expanded`), not selects it; clicking the empty canvas with nothing selected folds every manually opened bundle (the path's group stays open); a new tree resets them. Decision-node children are never bundled. Rules view is unaffected and stays the exhaustive listing. **Accessibility:** the diagram is a real `role="tree"` — flat `treeitem`s with `aria-level` / `aria-setsize` / `aria-posinset` / `aria-current` / `aria-selected`, roving `tabindex`, and Arrow Up/Down (visible order), Right (first child), Left (parent), Home / End, Enter / Space (select), Escape (clear selection). Accessible names read like "Branch chicken. Question: Salsa? 8 rows, 3 no, 5 yes. On your example's path." The SVG links are `aria-hidden`. **Rules** view (replaces the old Outline) flattens the tree into a table with one row per leaf — # / **If** (feature + branch chips joined by "and") / **Then** (label swatch) / **Rows** (`N · P%` + bar); the rule your example matches is tinted, `aria-current`, tagged "Your example", and scrolled into view. It is the linear reading of the model for screen readers, small screens, or huge trees.
- **KNN** (`KnnViz`): two views (the old Scatter view is gone — it only ever showed two of N features and contradicted the ranking). **Distance target** (default): the plot centers in the leftover canvas beside the floating card (Table fills the leftover sheet beside a docked card column); your example sits at the center, every rendered row is a dot placed by its *actual* multi-feature distance (honest for any number of features), each label owns a wedge (labels orbit the panned center just outside the fit ring, "N rows" until the last step, then "N votes"), and your example is a purple bullseye (ghost bullseye when empty, no caption). When the label set is wider than the 8-color palette, `groupLabels` keeps the 6 labels with the most votes (then frequency) as named wedges and folds the rest into one neutral **Other (N more)** wedge, so a 38-country label still reads as 7 wedges instead of 38 slivers. The radial scale is **neighborhood-first**: the inner 62% of the radius covers 0…2× the k-th neighbor's distance and the rest compresses out to the farthest row, so the nearest rows are visibly nearest even on a 1000-row sheet; guide rings are labeled with their real distance (a tick that would land on the k-ring is skipped). On the last step, **spokes** run from the center to each voter, a dashed purple **k nearest** ring encloses them with numbered dots, and the wedges switch to vote counts. **Dense regime** (k > 30): spokes and numbered badges are dropped, the k-disc becomes a shaded solid ring, and each wedge gets one **vote arc** just outside the ring whose thickness is proportional to its share of the same k-nearest votes as the card's `VoteTally` (the winner's arc is bold) — hovering an arc opens a popover with the category name and `N of k votes`; rank badges appear only on hover. **Ties** at the k-th distance (common with categorical features) are shown honestly: tied rows are hollow dots on an amber band at that radius. **Semantic zoom:** rows are binned by (wedge, distance ring, angular sector) at the current zoom into count **bubbles** (radius grows with √count, capped at 18px; amber when the whole bin is tied). The cell size adapts to how many rows are drawn (`binSize`: 20px × √(rows/100), clamped 22–64px, so 400 rows bin at 40px and a 50-row sheet stays as dots); zooming in shrinks the cells in data space so bins split into smaller bubbles and finally individual dots. Hovering a bubble opens a BubbleCard ("4 rows · Taiwan · 2 away · 1 vote · Click to zoom in"); a press that does not travel more than 4px zooms 2.2× on it (handled in the frame's pointer up, because drag-to-pan captures the pointer and a plain `click` never reaches the bubble). Hover state is cleared whenever the viewport changes or the pointer leaves the frame, so a card cannot stay pinned to a mark that re-binned away; the k-ring, arcs, spokes, labels, and guides are `pointer-events: none` so the filled disc never blocks hover on the neighbors inside it. Ranked neighbors stay as individual dots (with badges) in the normal regime; the hovered rail row's dot is always pulled out of its bubble. The target **zooms and pans**: mouse wheel, drag (`grab` cursor), keyboard `+` / `-` / arrows / `0`, plus a floating tool stack (Zoom in / Zoom out / **Zoom to the neighbors** / Fit everything). Dot sizes stay constant under zoom; a new example resets to Fit. Same-label rows are spread around their wedge with a golden-ratio walk so equal distances do not stack. Only the closest 400 rows are drawn ("400 of 1000 rows shown"). **Table** lists your example pinned first, then the first 100 rows ranked by distance (first k marked as voters), each feature cell showing the row's value and ✓ match or Δ difference; its empty state is a single "Nothing to compare yet." The floating **NavigatorCard** is one 300px card with three KNN states. Shared chrome: Play + stepper, a lede (statement + metrics), a **NEAREST NEIGHBORS** list (3 preview rows), and a full-width **See all rows →** footer (disabled until there is a prediction). Head and footer stay pinned; the lede and neighbor list scroll when the card hits the canvas. **Place:** "**Your input is placed in the center**" + feature rows (name · dotted leader · value) + 3 dashed placeholder slots ("Neighbor Name"). **Measure:** "**Your nearest neighbors are mapped**" + the same `VoteTally` with muted senary fills + real neighbor rows (label title, `Row N · d away · n/N match`) with empty dashed badges. **Vote:** "**Male** wins with 21 of 31 votes" + colored tally + numbered label-colored 18px badges; Neighbor rows use a neutral-secondary fill on hover. **See all rows →** jumps to the Table. The card is Target-only in dock layout — Table is full-bleed. In canvas layout Table docks the card column like the Train rail (same 300px card geometry, no card shadows). The live announcement still uses `summarizeVotes` so it never runs past five labels. Hovering or focusing a neighbor highlights its dot and opens a **RowCard** (`role="tooltip"`) with per-feature deltas; hovering a dot does the reverse. Steps: Place your example → Measure distances → The k nearest vote. The Output card does not repeat the neighbor chips.
- `ModelActions.tsx` is the shared **Scorecard** / **Save model** button pair (Save model is the export entry point, `floppy-disk`) used by both the Data Results card footer and the Test metric strip. ## Known Gaps

- No in-app CSV upload (CSVs are build-time via the drop folder) or side-by-side comparison of two saved models
- No A.I. bot train/test animation (the Train button only shows a short Training… pause)
- Save model (export) is a session-local model card + `getPrediction` snippet, not a real App Lab import
- Sheet columns are fixed-width, so wide datasets scroll horizontally beside the Train rail rather than flexing to fit like the Figma frames
- Tree trainer is a small canned-depth ID3 stand-in, not production `ml-cart` (depth sweep, regression). Guided tree nodes show sample count and impurity drop; they are not the full PM contribution tooltips
- KNN distance is not feature-scaled and the UI no longer says so (the rail footnote was cut for text budget); the Table's Δ columns are the only place a student can notice a large-range feature dominating
- Viz accessibility is designed in but not audited with a real screen reader: the tree has no type-ahead, the KNN target's individual dots are mouse-only (the rail, table, and live region carry the same information for keyboard users), the RowCard is `role="tooltip"` without `aria-describedby` wiring, the trace dots are buttons rather than a slider, and opening a tree node in place is not announced beyond `aria-selected` (the detail text is in the node's accessible name only after re-reading it)
- The KNN target draws the 400 nearest rows and hides the rest behind a note; zoom is manual (Fit by default, **Zoom to the neighbors** is a button) and the wedge spread is a golden-ratio walk, not a collision-avoiding layout. Exact-distance ties (all-categorical features) still land on one band — bubbles keep it legible, but a tied band of hundreds of rows is a ring of "2"/"3" bubbles, not individual dots, until you zoom
- The cardinality guardrail counts distinct values as typed (a blank cell is a value), so blank-heavy columns like ramen `Top Ten` count "" as a category and appear as an unnamed wedge/option. Shuffle skips blank category values so it still fills the field. The 8-label fold threshold is the palette size, not a tuned readability number
- With bundling off (the default), very wide categorical splits (dozens of branches) produce a stage that Fit shrinks to the 0.25× floor (illegible) and that must be zoomed and panned to read; Fit centers an overflowing tree rather than aligning the root. Bundling is behind a dev flag until playtests say whether the wall of pills is a learning moment worth keeping; an open bundle has no per-bundle close affordance (click the canvas), and bundle members are not summarized in the Train rail
- Opening a node in place reflows its siblings, so the tree shifts a little on select; the canvas pans to keep the opened card visible but does not animate the reflow itself
- Spreadsheet has no sort, filter, fill-handle, or undo stack
- Training is still main-thread; a Web Worker would only matter for datasets an order of magnitude larger than the current drop folder. Column type inference is all-or-nothing (ramen `Stars` is categorical because of "Unrated"); a ≥95% numeric threshold is a pending data-quality follow-up
- Classic `AiLabWorkspace` / `GuidedDatasetPanel` pullback tables still render every row (they share the stats cache but are not virtualized)
- Studio KNN holdout is always the last 10% (deterministic), not a random split; guided KNN still scores the whole sheet
- Playtest leftover (on purpose): KNN, other datasets, cell edit, and Save model stay locked. Dev panel can still remount those knobs. Auto-pretrain on Bird / mammal / fish without a feature list still picks **Animal** — Level 2 ships an explicit feature list so that does not happen in the stagger
